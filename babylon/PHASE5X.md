# Phase 5X: Workbench Refinements

**PHASE 5X IS CLOSED.**

## Objective and approved scope

Phase 5X delivers five bounded refinements to the existing Object Recipe
Workbench. It adds no new geometry operation or recipe representation.

1. Registry object-type selection immediately refreshes parameter controls.
   Selection alone does not save the recipe; saving remains explicit through
   the existing part-save action. Standard Guided mode continues to default
   to `SimpleBlock`.
2. An optional preview-only visual-anchor overlay displays translucent red
   cubes at evaluated anchor positions. The selectable display sizes are
   2x2x2 and 4x4x4. The overlay is not recipe geometry and does not affect
   evaluation or Package 1.0 output.
3. Raster stack authoring supports deterministic occupied-mesh centering and
   `dHorz` / `dVert` placement controls mapped to the selected construction
   plane: XY maps to X/Y, YZ to Y/Z, and ZX to Z/X. Placement does not change
   raster geometry semantics or connected-position solving.
4. Raster occupancy is presented as a spreadsheet-style grid with column
   headers, row headers, and one checkbox per cell. Checkbox submission and
   row-major raster occupancy semantics are preserved.
5. New guided recipes offer Standard Guided Recipe and Raster-Only Recipe
   modes. Raster-Only mode creates no registry geometry part.

### Raster-Only representation

Raster-Only Recipe uses only the existing Recipe v0.6 model: `object.profile`
contains the authored raster, and a geometry-only `stackPart` uses
`geometry.type: "raster_stack"` and `geometry.profile: "object.profile"`.
The stack transform supplies placement; anchors are generated by the
unchanged evaluator. This is a guided authoring path for existing schema and
evaluator capabilities, not a new object type or schema construct.

### Architectural principle

> Geometry objects define themselves through the Object Recipe; consumers are
> responsible for interpretation, rendering, inspection, and export.

The Object Recipe remains the single source of truth. The established
Recipe -> evaluator -> Package 1.0 -> independent consumer/Plotly -> Babylon
pipeline remains unchanged.

## Frozen boundaries

Phases 5R-5W remain frozen. Recipe v0.6, the evaluator, Package 1.0,
independent consumer behavior, Plotly package interpretation, and Babylon
production behavior were not changed. Named root raster profiles remain
JSON-only; this phase does not expose them in guided authoring.

No schema, evaluator, Package 1.0, independent consumer, Babylon production,
or dependency changes were made. Standard registry-backed authoring and
existing 5V raster-stack behavior remain covered by regression tests.

## Intermittent browser failures investigated

Prior full serial Playwright attempts showed intermittent failures outside
Phase 5X behavior:

- The 5V spreadsheet-grid interaction initially had Playwright pointer events
  intercepted while using the intentionally hidden checkbox label. The
  browser test was updated to target the accessible checkbox and force the
  check; it still asserts the checkbox is checked. The focused 5V browser test
  and the final complete suite passed. This was a test interaction issue
  introduced by the intended spreadsheet presentation, not a geometry or
  output failure.
- Phase 5N `08-zomball-candidate` intermittently remained at “Loading
  reference fixture...” or saw `ERR_NETWORK_IO_SUSPENDED`; isolated reruns
  passed. It also passed in the final fresh-server complete suite. This is
  browser/page lifecycle or resource timing instability, not the Workbench
  change.
- The Inspector reset-camera interaction and malformed-coordinate smoke test
  each timed out in isolated full-suite attempts and passed in subsequent
  attempts; both passed in the final complete suite. These were not
  reproducible and were unrelated to Phase 5X Workbench paths.
- A clean `CI=1 npm run test:e2e` run started fresh preview and Streamlit
  servers after confirming the test ports were clear. It completed **20/20
  tests** successfully. No broad timeout, weakened assertion, or frozen
  contract change was used to get this result.
